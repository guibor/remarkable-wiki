# Explicit article refresh

The user requested refreshing an article even if it has already been downloaded.
Stay on main, continuing the Open PDF fix. v0.2.2 / backend protocol 4.

## Product decision

Download again appears in the completed/existing article card, alongside a clear
explanation that a new PDF is imported and the old copy/annotations are kept.
No replacement of live library files or automatic deletion. Current save folder
applies to the new copy; the captured article language/key do not follow later
search/language edits. Open PDF targets the latest verified native import.
Legacy imported records without a native ID can be refreshed too. Uncertain
imports stay blocked; normal repeated selection does not create a duplicate.

## Implementation and checks

The explicit refresh flag bypasses the completed-record guard and app PDF cache,
not native import safety. DownloadFresh uses the validated atomic downloader;
HTTP/validation failures leave the prior cache and history intact. Wikipedia's
own cache and PDF generation can still return unchanged content.
New tests cover fresh HTTP versus cache reuse, preservation after HTTP failure,
duplicate policy, legacy refresh, original language, Open plus refresh, and
blocked pending identity/import states.
