#+title: reMarkable Wiki

* Requirements
- Separate repository and maintained package for Wikipedia search/PDF reading.
- Reading-first product and announcement: provide the missing connection from
  desired content to a PDF in the native reader, rather than turn the e-reader
  into a browser. Keep reading/highlighting/annotation in the existing reader.
- Search and PDF generation use Wikipedia's public services directly from the
  tablet. No dependency on md-server, API keys, desktop or reMarkable cloud API.
- Search box, readable results, direct Download action, honest progress/errors.
- Incremental search after 500 ms of paused typing (two characters minimum).
  Search/Enter submits immediately, including a one-character query. Automatic
  searching must not hide/disable the keyboard or clear existing results.
  Immediately invalidate older requests when query/language changes; retain
  results on failures/cancellation. Downloading a visible result cancels search.
- Input must stay editable throughout each live-search transition, not only at
  the end of a callback. Do not force the keyboard back open after native dismissal.
- English default and Hebrew Wikipedia option; remember search language.
- Use the native reMarkable keyboard, not an app-owned keyboard. Open it from
  the query field/Keyboard button, reserve its actual overlap above the results,
  and hide it on explicit submission, download, folder navigation or app close.
  Leave the tablet's keyboard language/settings unchanged; Wikipedia language
  and keyboard layout are distinct. Preserve incremental search and Unicode input.
- Import through the editor's existing DocumentImporter. Do not write library
  metadata, modify existing documents, patch firmware, or restart per download.
- Configurable existing destination folder, remembered across app launches;
  default My files. Folder changes affect new downloads only. Use native import
  with the folder ID, not filesystem moves or library metadata writes.
- Show a prominent download/import status panel with article and progress.
  After matching native success, offer Open PDF for that exact imported document.
- Open PDF must remain visible after native import even when the callback's
  document object is opaque. Resolve the real native ID, verify the exact PDF,
  and persist it for subsequent opens; do not infer IDs from titles.
- Offer a quiet, underlined Refresh article action for an already imported article,
  including legacy history with no recorded native ID. Fetch from Wikipedia
  again rather than reusing the app cache; import a new copy into the current
  destination. Preserve the old document and annotations. Never refresh an
  unresolved in-progress import or automatically duplicate a saved article.
- Open PDF is the dominant completed-card action; refresh has no button border,
  smaller text, and a short explanation of new-copy/annotation preservation.
- Prepare a trimmed demo from the user's supplied recording for the Reddit
  draft; do not post it or change repository visibility without authorization.
- New PDFs follow normal device sync policy; this is not a
  cloud-exclusion feature. No claims of offline search or local PDF rendering.
- AppLoad entry, self-contained app payload, preserve all other installed apps.
- Pro first; responsive layout for Move, but qualify/install Move independently.
